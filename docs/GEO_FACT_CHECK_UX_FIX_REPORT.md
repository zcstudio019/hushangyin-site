# AI文章事实核验与审核阻断优化报告

日期：2026-11-02。项目：D:\Codex\hushangyin-site。本地验收：http://127.0.0.1:3000 。未部署生产，未调用付费AI。

## 1. 真实根因

原系统能够计算规则，却缺少完整的人工处理路径：只有行号和文本提示，不能选中编辑器对应原文；普通知识文章也统一生成NO_SOURCE阻断；保证性承诺规则与FAQ风险判断分别实现，否定语境可能不一致；误报没有独立复核入口，检查结果、历史生成提示及当前结论也不够清晰。

此次真实PostgreSQL隔离测试还发现，风险证据比较直接依赖JSON键顺序。JSON入库后键序可能改变，导致内容未变却被误判为证据变化。现按字段内容稳定比较，并兼容历史公开来源的旧哈希格式；没有改写历史审核记录。内部资料仍绑定内容、日期及updatedAt，真实变更继续失效。

## 2. 完成的交互

文章“生成溯源与事实核验”区域现在显示：

- 当前核验文章版本及保存检查时间。
- 必须修复、待人工核实、优化建议的数量，按严重程度排序。
- 问题类型、实际原文、正文行或知识来源。
- “定位并修改”：滚动到编辑器、选中相关文本，并按当前输入重新计算行号。
- “补充这项主张的核验依据”：直达现有来源输入区。
- “申请人工复核”：记录申请、版本及内容指纹，不改变审核/公开状态。
- “重新执行事实核验（已保存版本）”：保存版本绑定的结果，刷新已解决问题。

缺失项没有单一触发文本时明确说明“整篇文章或知识来源”，不伪造行号。原文已经修改且无法匹配时要求保存重查，避免跳到无关旧位置。未保存或保存中继续禁止审核与核验决定；加载的检查版本落后于已保存版本时也拒绝直接处理旧项。

生成时知识提示明确标为历史快照，不等于当前阻塞结果。公开来源与日期使用原编辑器维护，状态提示区区分来源填写、格式/版本检查及独立内容核验；不将网址可访问或格式正确当成金融事实真实。

## 3. 承诺识别与人工复核

共享保证性表述判定，避免文章和FAQ使用相互冲突的规则。覆盖保证放款、百分百通过、无视征信也能获批、确保获得贷款等明确表述，以及全角和零宽字符形式。

否定提醒如“不保证贷款获批”“不承诺百分百放款”“任何机构均不应承诺包过”不直接作为违规承诺；问答式语境仍列为待人工核实。添加反例验证：不需要资料就保证放款、不审核也保证放款、我们保证放款是否满意等不能靠否定词或问号放行。规则是辅助，不承诺覆盖所有自然语言表达。

复核复用现有RBAC与审计表：

1. 内容运营在草稿版本提出申请，相同检查项的未完成申请去重。
2. `/admin/geo/reviews/` 新增“AI文章事实复核待办”，显示近期申请中符合当前审核人独立资格的记录。
3. 独立人员在文章页核对全文/预览、风险等级、必要依据并填写不少于10字的专业判断，可确认判断或退回补充。
4. 作者、编辑、提交人不能复核自己的版本；无content.review权限者不能处理申请。
5. 真实承诺、隐私、不安全文本、缺少还款风险等必须修改项不能被复核勾选消除。B类真实承诺必须修改；本期没有超级管理员强行豁免入口。
6. 复核结论不等于正式审核或发布。正式流程仍是草稿→待审核→独立审核→授权发布。

申请及决定保存在原audit_logs，包含操作者、文章、revision、内容指纹、理由、决定和必要证据快照。不存在新登录、角色或第二套发布系统。资料变更、角色失效或文章新版本会重新校验，旧判断不自动挪到新正文。正式content_reviews中的当前版本风险判断同样复用，避免已经完成正常审核后仍显示旧的专业判断待办。

## 4. 按事实主张管理依据

普通基础知识和不含具体主张的一般实操可进入人工审核，不强制外部网址或银行产品资料；独立人员仍须保存专业判断。AI文章正式审核保留七项金融内容核验，并附风险等级、判断及必要的逐项证据。

对具体银行政策、产品、利率、额度和数量条件，根据实际正文提取主张。每条缺少对应依据的主张显示独立阻断项，不能仅通过选低风险解决。支持：

- 原有已核验公开来源：标题、网址、核验日期、适用期限及对应正文段落。
- 原有受控内部资料目录：标题、内部编号/版本、实际核验日期、对应条款及版本快照，不强制HTTPS。

复用risk-evidence校验，逐项记录claim→sourceIndex或catalogId/catalogVersion的关系。来源过期、停用、版本改变、无有效核验人或不存在均拒绝。源资料管理仍走原超级管理员授权及近期密码验证，不开放文件上传。

内部依据只用于授权后台核验，不注入公开来源列表，不发送给AI模型。不得为获得通过率编造标题、产品条件或日期。C文章的示例利率没有真实资料，本次没有替它伪造来源或批准为金融事实。

## 5. 版本与服务端保护

新增接口：`GET/POST /api/admin/geo/articles/{id}/facts/`。

| 操作 | 权限与行为 |
| --- | --- |
| GET | content.read，读取授权文章的当前检查、当前版本申请和依据选项 |
| POST check | content.read，版本校验、数据库事务、保存检查结果和审计，不更改正文revision |
| POST request | content.update，草稿限定、理由校验、申请去重 |
| POST decide | content.review，独立性、固定版本、申请归属、逐项证据、重复处理校验 |

POST均执行同源CSRF、32KB请求体限制、Zod及原数据库写入限速。操作者来自服务端会话，客户端不能指定actorId。拒绝把手机号、凭据等写入判断说明。检查记录用原articles.complianceReport，人工决定用原audit_logs；没有迁移、没有重置数据库。

文章版本及内容/来源指纹同时绑定，真实并发冲突仍拒绝；保存新版本后旧申请、决定不能用于新内容。已发布文章仍保留独立公开快照。基于JSON字段的比较采用稳定键序，公开来源比较实际字段，内部资料继续保留版本指纹，不通过忽略真实字段来消除风险。

## 6. 实际验收

采用本机Edge/Playwright访问当前服务及真实本地PostgreSQL。内置浏览器连接桥不可用后使用该可用环境，不以Mock页面代替。三篇文章均是明确的本地虚构规则夹具，只有元数据用于模拟AI草稿来源，没有调用模型。

| 场景 | 真实结果 |
| --- | --- |
| A 否定保证表述、基础知识、无URL | 无承诺MUST_FIX；点击原文选中第3行，插入两行后重定位第5行；保存版本2并持久化检查 |
| A 独立复核 | 作者和匿名被拒绝；审核中心可见待办；独立审核员实际页面确认专业判断，文章仍DRAFT，未自动批准 |

| B 真实保证放款 | 提交被拒；独立复核试图放行返回MUST_EDIT；定位并改成否定提醒后保存版本2，旧风险消失，可提交审核 |

## 9. 使用方法与边界

运营进入原文章编辑页，按卡片定位修改或申请复核；保存后重查。公开来源仍在原来源区填写；需要受控资料时由授权管理人员在原审核中心登记。独立审核员从“AI文章事实复核待办”进入文章，阅读全文或原预览，核对相应依据后记录判断；正式审核和发布继续分别操作。

普通基础知识现在允许专业判断而不强制URL，这是对前一版“一律来源阻断”的明确调整；以前报告中的旧规则仅代表历史。真实承诺、隐私及无依据具体事实仍保持阻断。规则和复核界面不能代替专业人员确认事实与适用日期。

未在共享开发库实际停库或部署多实例压测；未审核真实银行产品资料、真实利率或真实客户案例；没有重新进行付费AI生成。本次不包含内部文件存储、自动外网事实抓取、自动发布或生产开通。
