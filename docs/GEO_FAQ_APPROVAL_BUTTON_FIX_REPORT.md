# 沪上银 GEO FAQ“审核通过”按钮专项修复报告

日期：2026-10-30。项目：`D:\Codex\hushangyin-site`。

## 1. 真正原因与实际复现

在修改业务代码前，使用本地实际服务 `http://127.0.0.1:3000`、现有PostgreSQL、虚构内容运营A和独立内容审核员B复现。内置浏览器连接失败后，采用项目已有Playwright驱动真实Edge headless，并监听页面发出的请求，没有使用Mock数据库。

发现两个独立的提交前阻塞：

1. **说明填“无”：浏览器阻止提交，未发送请求。** `src/components/forms/GeoForms.tsx` 的 `WorkflowForm` 为核验说明设置 `minLength={10}`，但标签没有说明最低长度，表单使用默认浏览器校验，没有把 `invalid` 转成组件内提示。七项勾选、来源完整、说明填“无”后实际点击：`validity.tooShort=true`、审核POST数量0、组件的反馈文本为空，`onSubmit`/`action`根本未执行。服务器本来也要求至少10字，因此不能靠删除校验让“无”通过。
2. **来源缺失：按钮被禁用。** 内容详情将 `policy.missingItems` 转为 `approvalBlocked`，`WorkflowForm`据此禁用“审核通过”。原因和补充路径主要显示在上方，按钮附近缺少直接解释。实际浏览器复现缺来源FAQ按钮禁用，点击不能发请求；清单勾选不能替代来源。审计时原60组待审核FAQ均无引用来源。

另在修复后的截图复核中发现反馈持久性问题：详情页的 `key=flow-版本-状态-是否公开` 会在审核后刷新时重新挂载表单，本地成功文本随之清空。保留按版本重置表单的安全行为，改为同时依据服务端已审核状态显示持续成功提示，不靠延迟刷新或伪造前端状态解决。

分类结论：原短说明/缺来源问题属于 **A：没有发请求**，不是数据库更新失败或缓存旧状态。请求真正发出后的权限、改派、版本和异常路径也分别验证，详见下文。

本轮数据库已有激活的内容审核员，不再是上一轮“没有审核角色账号”的状态。没有修改原员工角色、密码或独立审核条件来解决本次问题。

修改前证据：`test-results/faq-approval-before/result.json`、`native-validation.png`、`source-disabled.png`。复现记录为 `postCount=0`、`tooShort=true`、`feedback=""`。

### 审核说明与操作反馈

- 通过和退回均须填写具体说明：去首尾空白后至少10字，最多1000字。明确说明不能只填“无”“同意”，应记录实际来源、支持的事实与适用时间，或需修改的问题。
- 工作流表单使用 `noValidate`，由共用业务规则显示中文反馈；这只接管浏览器的静默拦截，不取消任何服务端校验。说明错误定位到说明，清单缺项定位到未勾选项。
- 来源缺失时仍禁用通过，但按钮附近列出缺失字段，说明须由作者撤回、补充、保存、重新提交，并重新分配新版本。
- `useRef`提交锁及禁用fieldset阻止重复提交；审核按钮显示“审核处理中…”，按钮旁显示正在提交。
- 只有现有API返回成功才显示成功并刷新。状态进入APPROVED后，由服务端状态持续显示“审核已通过”，刷新仍在；发布人可看到“发布到官网”，审核员看到交由发布人员操作。
- 网络断开、15秒超时、服务/数据库不可用显示结果尚未确认及刷新核对指引，不自动重试。浏览器取消等待不保证服务端事务一定取消，因此不误称“肯定没有保存”。

## 3. API请求与响应

继续调用 `POST /api/admin/geo/faqs/{id}/workflow/`，文章共用原路径中的 `articles` 类型。

请求形状保留：

```json
{
  "action": "approve",
  "revision": 3,
  "note": "记录本次真实核验过程的具体说明",
  "checklist": {
    "sources": true,
    "promises": true,
    "relationships": true,
    "cases": true,
    "promotion": true,
    "privacy": true,
    "human": true
  }
}
```

其中示意说明不是预填的默认核验结论。实际测试只使用合成软件技术内容和对应Next.js官方站点地图技术说明，不把技术来源当作融资事实依据。

| 场景 | 真实结果及反馈 |
| --- | --- |
| “无”/说明过短 | 前端明确报错、定位，0 POST；绕过前端直接调用仍400 |
| 人工清单缺项 | 前端报错、定位，0 POST；直接API仍400 |
| 来源缺失 | 按钮旁明确缺失与正式补充流程，直接API 400，不写通过记录 |
| 内容运营无审核权限 | 页面中文说明，真实API 403 |
| 有权限作者试图自审 | 页面说明独立性，真实API 403 |
| 打开页面后任务被改派 | 真实API 403，按钮附近显示由指定审核员处理/联系管理员 |
| 打开页面后作者撤回 | 真实API 409，显示版本变更、撤回或他人处理及刷新指引 |
| 有效独立审核 | 真实POST 200，状态APPROVED，产生一条对应版本审核记录和一条通过审计 |
| 有效授权发布 | 原API 200，公开页200，Sitemap包含URL |
| 断网/无响应 | 浏览器请求故障注入，显示连接失败/15秒超时，解除提交锁，不假报成功 |
| 服务不可用 | 浏览器受控503响应注入，显示服务/数据库不可用，不暴露内部信息 |

403/409/400是实际审核服务返回，不是模拟的权限或业务结果。断网、503与超时是单独标记的浏览器故障注入；成功审核和发布没有拦截伪造响应，而是延迟后放行真实请求，再查真实数据库。

## 4. 数据库状态、审核和审计

## 7. 当前使用方法

进入 `/admin/geo/reviews/` 或FAQ详情。若提示来源缺失，作者先撤回并补充真实来源，保存、重新提交，由合格独立审核人审核。七项勾选后，填写至少10字、符合实际核验过程的说明，不能填“无”替代核验。

点击后看到“审核处理中…”，成功则看到“审核已通过”。审核人员没有默认发布权限，应由具有发布权限的人员进入待发布内容并单独点击“发布到官网”。如超时或断网，先刷新查看当前状态和审核记录，避免凭猜测重复操作。
