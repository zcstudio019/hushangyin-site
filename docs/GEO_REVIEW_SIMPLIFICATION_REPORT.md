# 沪上银 GEO 内容审核流程简化报告

日期：2026-10-30。项目：`D:\Codex\hushangyin-site`。

本次在现有审核系统内完成FAQ风险分级、必要证据、综合确认、批量分配和逐条低风险审核。复用原认证、角色权限、版本、审核记录、资料目录与发布流程；不新增数据库表，不部署生产，不自动审核或发布历史内容。

## 1. 原规则为什么复杂

原`workflow`对FAQ和文章统一执行`requireCurrentSources`，无论只是“银行流水是什么”的定义，还是具体银行产品利率，都需要有效HTTPS网址、标题及核验日期。界面也一律要求七项详细核验，缺少来源直接禁用通过。因此60组无公开来源的历史FAQ都被同一门槛阻塞，无法表达“依据专业知识人工确认”这一合理的低风险判断。

本次将FAQ的专业判断和事实证据分开：来源要求随主张变化，作者独立性、真实权限、版本及单独发布保持。文章和AI生成文章继续原详细审核，不因FAQ简化而放松。

## 2. 新风险等级与防绕过

| 等级 | 典型内容 | 审核要求 |
| --- | --- | --- |
| 基础知识 LOW | 银行流水、一般交易概念、无具体利率数值的概念解释 | 综合确认、至少10字专业判断；不强制外部网址 |
| 融资实操 MEDIUM | 一般申请材料整理、办理准备、融资规划 | 一般建议说明适用条件；涉及具体银行要求、审批条件或数量判断时，逐项关联可核验证据 |
| 高风险 HIGH | 具体银行、适用政策、具体利率/成本、产品条件、额度、银行关系及案例等 | 对应真实证据、综合确认、七项详细核验、具体意见；不得缺证据通过 |

通用概念中的“利率”一词不自动等于具体利率主张。识别关注具体银行、时效、数值、产品和政策条件。数字和中文数量、全角百分号等表达统一识别；例如“3年／三年”“月息三厘”不能因写法改变而免核验。

建议等级和证据主张由服务端每次根据当前问题、答案重算；审核人员确认最终等级，可提高，不能低于已识别的必要核验范围。客户端改成LOW或调用旧接口不能绕过具体主张核验。保证性承诺、疑似客户手机号/身份证等内容先阻止通过，不能凭一份证据免除合规问题。旧七项契约也不能绕过这些阻止条件。

规则属于辅助和最低范围，不是金融事实识别器或合规许可；存在误判、漏判的可能。审核人员须阅读全文，发现未标记的重要主张时提高等级并补充证据，不能将自动建议当作已核验事实。新政策标识为`risk-v1`。

## 3. 来源与核验依据

### 低风险和一般实操

可以不填外部URL，审核人员以真实专业判断填写10—1000字意见，确认真实性、融资宣传合规、客户隐私和必要依据。不能只填“无”“同意”。具体版本、审核人、时间、确认等级、判断依据保存到原`content_reviews.checklist`及`note`；对应审计继续写入原表。

### 具体主张和高风险

每项主张必须选择对应依据；未填、已停用、已过期、核验人失效或对应内容改变时不能通过/发布。允许两种依据：

- **公开来源**：复用原FAQ已有来源，核对标题、HTTPS网址、实际核验日期及适用时间；新审核记录保存所对应的具体主张和证据快照。
- **受控内部资料**：复用原`article_sources`目录，类型`INTERNAL_BANK`；由超级管理员重新验证当前密码后登记标题、内部编号及版本、适用条款、实际核验日期、可选截止日期及启停状态。无需公开HTTPS网址。审核员可查看对应条款、编号和时间，必须人工核对原件确实支持主张。

内部目录是可追溯的核验登记，不自动证明原件存在或金融事实正确。原件应保存在负责人已有的授权存储，本次不接收文件、不建设文件上传模块，不将客户资料作为证据收集。日期不自动预填；服务端拒绝未来核验日期及无效时间范围，不编造核验时间。

证据快照保存在具体版本的审核记录内；内部证据同时绑定页面所见的目录版本，打开页面后资料变化会拒绝审批，须刷新重新核验；发布时再次重验当前条件和指纹。审核后资料更新、停用、过期等会阻止使用旧结论发布，需要修改为新版本并重新核验。不会静默覆盖旧审核历史。

内部资料目录、编号和条款仅在授权后台使用，不写入公开FAQ快照；AI检索、引用重验、生成模板的公开参考资料列表显式排除内部目录，防止因复用资料表而发送第三方模型。该隔离有真实测试库回归。

### 旧记录与旧客户端

已有来源、审核及版本数据不改写。已保存的新版风险判断按版本读取。旧版七项请求对基础内容仍保留原详细契约；如果内容含具体主张，须升级为带风险和证据对应的审核请求。不能借旧接口免除新主张检查。旧版高风险审核未具备新核验记录时，不能直接按旧结论发布。

## 4. 界面与批量操作

FAQ主要审核区显示问题和答案、风险等级、按需证据、综合确认、审核意见和通过/退回。基础及一般实操不显示七项清单，高风险保留详细清单；审核分配和旧引用收进折叠区，历史版本仍保留。稿件编辑器将公开来源标为选填，说明内部依据在审核时关联。

错误显示具体阻塞，例如缺少具体利率/银行条件依据、风险等级不能调低、内部资料失效、证据已变更、当前账号不符合独立性。原有处理中、防重复点击、成功持久提示和网络异常反馈继续保留。

入口：`http://127.0.0.1:3000/admin/geo/reviews/`。

1. **批量分配**：展开“批量分配与逐条核验”，加载最多100条，选中待分配内容，选择对本批每条都合格的独立人员。可全选用于分配；服务器逐条验证当前版本、启用/首次激活、权限及是否参与版本。
2. **低风险批量审核**：每条展示完整答案；逐条填写判断依据、逐条勾选确认，再提交。没有“全选已核验”按钮，每条生成自己的审核和审计记录。
3. **中高风险**：不能批量批准，进入单条详情核对对应依据。
4. **正式发布**：仍由具有发布权限的人员进入待发布内容，单独“发布到官网”。批量接口不支持publish，审核不会自动公开。

批量每条是独立事务，返回逐条结果和成功/失败数量，不宣称整个批次原子成功。部分失败或网络异常时应重新加载核对，不能盲目反复提交。

内部依据管理员入口在同一审核中心的“受控内部产品依据”折叠区；审核人员无需查看客户线索或提升为超级管理员即可使用已登记依据。

## 7. 未完成事项和边界

- 没有代替真实审核员对原60组做最终专业判断或批量批准，没有给原员工自动提权。
- 风险规则不是全量金融事实核查；未识别主张仍由授权人员提高等级、补证和处理。真正的来源可靠性/原件授权也须人工确认，不由API声称已证明。
- 本期只管理受控内部资料目录，不建设内部文件存储、上传、自动真实性核验或银行产品接口。
- 发布前重查证据；已发布内容的周期巡检、证据过期后的自动下线未实现，需运营按适用日期定期复核。
- 无来源但专业判断通过的基础FAQ本期可公开；原AI知识检索仍维持其已核验公开引用策略，不自动把内部依据或新来源类型送模型。扩展AI知识溯源需另行评审。
- 未配置AI密钥、未调用真实AI、未部署生产或修改生产开关。旧版专项用例未全部重写，新规则以本报告实际执行测试为准。
