# 沪上银 V1.5.3 内容审核发布闭环专项修复报告

日期：2026-10-30。项目：`D:\Codex\hushangyin-site`。仅本地 Next.js 3000 / 既有 PostgreSQL 55432，未部署生产。

## 1. 实际原因与账号检查

审核和发布 API 原本已存在，并非没有实现：`src/features/geo/service.ts` 的 workflow 已有 submit、approve、reject、publish、offline、withdraw，原 ContentReview 保存审批版本和决定。

本次核对发现：

- 原2个账号分别为1个有效 SUPER_ADMIN、1个 FINANCING_ADVISOR。原超级管理员的权限映射包含 content.review、content.publish；顾问没有内容审核权限。
- 原60组FAQ全部为 IN_REVIEW，authorId、editorId 均指向导入它们的超级管理员；目前没有另一个真实的独立审核账号。
- 原详情页以 `can(actor, "content.review") && item.editorId !== actor.id` 决定审核按钮。导入人打开本人内容会被防自审规则挡住，因此只看到撤回审核。原文章详情共用同一条件，也存在相同的解释缺失。
- 原提示“内容正在审核或当前账号无编辑权限”混合了两种不同情况，没有说明自审限制；没有统一审核中心，也没有待发布入口。
- 原FAQ只有在关联文章里才可能显示，没有独立公开列表、详情URL或FAQ Sitemap条目。FAQ缺少编辑版本快照，只有当前草稿、公开快照及审批记录。
- 原问题库没有说明内部选题与公开内容的关系，原保存判断只检查关联文章ID，没有充分验证其公开状态，也没有状态变更历史展示。

没有取消防自审来让导入人批准自己的内容，也没有自动给顾问或运营人员提升权限。现在同时校验原作者、当前编辑人、当前提交人与审核人不同，前端解释原因，服务端仍拒绝自审。

## 2. 修复功能

### 统一审核中心

新增 `/admin/geo/reviews/`，并加入原GEO导航。复用原 ContentReview 和工作流，没有第二套审批系统。

包含待审核文章、待审核FAQ、已通过记录/待发布、已驳回记录及全部审核历史，可按类型与标题筛选、分页，显示作者、真实提交时间或标明的历史导入时间、当前版本、当前状态、审核版本、审核人、时间及原因，链接到原内容详情。

没有审核权限时明确显示“当前账号没有审核权限，请联系超级管理员。”超级管理员遇到本人内容时显示不能自审的原因。只有一名有效超级管理员时，审核中心提示安排另一位独立审核人，并提供原员工管理入口；不会自动新增真实员工或修改权限。

### FAQ / 文章工作流

数据库继续使用原 DRAFT、IN_REVIEW、APPROVED、PUBLISHED、ARCHIVED 枚举。APPROVED 显示“已审核（待发布）”。驳回保留原 REJECTED 审核决定，产生新草稿版本；列表和详情依据版本关系显示“已驳回（待修改）”，没有另造一套状态枚举。

完整流程：保存草稿 → 提交审核 → 独立审核人通过 → 待发布 → 授权人点击“发布到官网”。驳回必须填写原因，作者须修改并保存新版本后才能重新提交。仅撤回、重新提交不能假装已修改驳回内容。

待审核页面直接展示全文、引用来源、缺少来源的具体提示和风险核验要求，不必先撤回才能阅读。编辑锁定、没有编辑权限、没有审核权限和不能自审分别解释。只有作者、编辑人、提交人或授权审核管理员可撤回。审核日志显示决定、人、版本、原因和时间；文章与FAQ都可查看受保护的历史内容快照。

FAQ必须有实际非空答案才能提交审核。通过与发布均验证核验清单及有效引用来源。未经审核不能发布；发布只复制已通过的具体版本。已发布内容修改后生成新草稿，旧公开快照保持；新版本批准并发布后才替换。失败的发布事务不会改变公开状态。

新增独立 `content.unpublish` 权限。超级管理员拥有全部原内容权限和下线权限；内容运营仍只能读取、创建、编辑和提交；融资顾问不能调用审核中心或工作流API。所有写请求沿用同源、会话、RBAC、限流和Zod校验。

成功的提交、审核、驳回、发布、下线、编辑及选题状态变更均保存审计。自审、越权撤回和未审批发布的策略拒绝也会留下不含正文或凭据的审计事件。

### 公开FAQ

- 列表：`http://127.0.0.1:3000/faqs/`，支持分类筛选和分页。
- 稳定详情：`http://127.0.0.1:3000/faqs/{FAQ_ID}/`，不因问题标题修改而换URL。
- 从原 `/insights/` 知识库提供链接；共用官网Header/Footer、深蓝金色样式，融资知识导航在FAQ页面保持高亮。
- 仅读取 isLive、publishedSnapshot、publishedRevision 与对应 APPROVED 审核记录均一致的内容。分类与答案来自公开快照，不读取未审核草稿字段。
- 服务端HTML、独立Title/Description/Canonical、FAQPage JSON-LD、公开时间、引用、相关文章、风险提示及咨询CTA。
- 复用安全Markdown渲染和结构化数据转义；不将未审核内容通过公开URL或Sitemap暴露。
- 详情、列表及Sitemap使用现有 force-dynamic 按请求读取PostgreSQL，没有新增内容缓存。因此发布/下线后下一次请求立即反映，无需重建或额外标签失效操作。浏览器已实测发布后加入Sitemap、下线后404并移除。

结构化数据用于表达页面语义，不保证搜索引擎展示FAQ富媒体结果。

### 融资问题规范化

保留 OPEN待规划、PLANNED已规划、ANSWERED已解答、ARCHIVED已归档。

问题是内部选题，不生成空白公开问题页。列表与详情增加状态说明、关联文章数量、是否有公开解答、创建文章及查看关联文章入口、状态变更历史。创建文章会预填题目、分类和关键词，在事务内保存多对多关联并同步原主关联字段，草稿阶段进入已规划；不覆盖原问题或来源。

只有存在实际线上文章快照时才算已解答。没有公开解答时，界面禁用该选项，API也明确拒绝伪造已解答。发布/下线重新计算全部关联文章：仍有有效公开解答则保持已解答，否则回到已规划；编辑线上文章的草稿不影响旧快照的解答资格。归档不会删除内容或关联，可恢复；保留历史草稿关联时恢复为已规划，有公开解答时恢复为已解答。

状态变更记录复用 audit_logs，保存原状态、新状态、操作人/系统、时间和原因；不会补造旧100题之前未记录的历史。

## 4. API 清单

| 接口 | 用途与检查 |
|---|---|
| GET `/api/admin/geo/reviews/?view=pending/approved/rejected/history` | 审核队列与历史，需content.read；支持type、q、page |
| POST `/api/admin/geo/faqs/` | 创建草稿，需content.create |
| PATCH `/api/admin/geo/faqs/{id}/` | 保存新草稿版本，需content.update；审核中锁定 |
| POST `/api/admin/geo/faqs/{id}/workflow/` | 沿用submit/withdraw/approve/reject/publish/offline，按操作分别校验update/review/publish/unpublish |
| POST `/api/admin/geo/articles/{id}/workflow/` | 复用同一审核与发布实现，同样防自审 |
| POST `/api/admin/geo/articles/` | 可选questionId，在同一事务创建文章和选题关联 |
| PATCH `/api/admin/geo/questions/{id}/` | 规范状态，拒绝没有公开解答的ANSWERED |

公开FAQ页面不是后台API的匿名代理；内部预览及历史快照页面必须身份认证，仍禁止索引。

## 5. 真实浏览器验收

使用本地实际3000服务、Edge及真实PostgreSQL，随机凭据的合成内容运营、独立超级管理员和顾问分别登录。没有使用Mock替代本节业务验收，也没有使用真实客户数据。

`npm run test:reviews` 覆盖10组真实流程及20个视口组合：

1. 浏览器创建FAQ草稿并提交；匿名草稿/待审核URL404，作者发布403，顾问审核API403、匿名401；运营人员看到清晰的无权限提示。
2. 审核人在统一中心找到待审核任务并驳回；原因可见，未修改直接重提409。
3. 作者修改、保存新版本、重新提交；另一账号完成人工清单与说明并批准，此时仍未公开。
4. 点击“发布到官网”，PostgreSQL保存对应公开版本，公开详情、无JavaScript HTML、分类列表、Canonical、JSON-LD及Sitemap一致。
5. 修改已发布内容产生新草稿，公开旧版本不变；未审核版本直接发布409且不破坏线上内容。重新审核发布后在同一URL替换。
6. 下线后详情404并从Sitemap移除，审核版本、人、时间、原因及审计持久保存。
7. 内部融资问题创建关联人工文章，草稿已规划；独立审核发布后回写已解答，可以查看关联公开文章；下线后回到已规划。
8. 有未公开草稿也不能伪造已解答；问题可归档并恢复，状态历史真实记录。
9. 超级管理员自己的内容同样不能自审，前端解释、API403并保留策略拒绝审计。
10. 375、768、1024、1440像素下检查审核中心、FAQ编辑、问题库、公开列表和详情，没有文档水平溢出和未捕获页面异常。

## 6. 超级管理员如何审核和发布原FAQ

1. 进入 `/admin/geo/reviews/`，选择待审核FAQ，点击“查看与审核”，核对全文、引用及历史。
2. 若提示本人创作/导入，需负责人在原 `/admin/settings/users/` 安排另一位真正独立的授权审核人员。当前固定角色体系中只有超级管理员有审核权限；本轮没有擅自给现有融资顾问提权。
3. 原60组FAQ没有填写有效核验来源，且均属于原超级管理员。请先由作者撤回，补充真实来源、核验日期和必要的内容修订，保存后重新提交；不得为了通过系统随意填入不相关网址。
4. 独立审核人在清单中逐项核验，填写至少10字说明，再审核通过；需要修改则填写驳回原因。
5. 有发布权限的人在“已审核（待发布）”状态点击“发布到官网”，通过“查看官网已发布版本”进入 `/faqs/{id}/`。

原60组FAQ保留待审核，没有批量批准或自动发布。当前 `/faqs/` 没有已发布内容时显示空状态是正确的安全行为，不是本轮流程失效。

## 7. 融资问题如何转成公开文章

进入 `/admin/geo/questions/` → 点击“创建文章”或详情中的“从此问题创建文章” → 补充网址标识、摘要、正文和真实引用 → 保存草稿，系统建立关联并标记已规划 → 提交审核 → 独立人员审核通过 → 授权发布 → 原问题自动显示已解答及公开文章入口。下线最后一篇公开解答后回到已规划，历史关联仍保留。
