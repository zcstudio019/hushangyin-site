# 沪上银 V1.6 私有预发布操作手册

本手册是准备材料，未在 ECS 执行。**先审计，后取得具体操作授权；不要直接照抄全部命令上线。** 不包含公网启用、DNS 修改或 RDS 操作。

## 1. ECS 只读审计

将 `deploy/ecs/audit-readonly.sh` 单独传到服务器后执行：

```bash
sudo bash ./audit-readonly.sh > hushangyin-ecs-audit.txt
```

脚本不安装软件、不停止服务、不输出环境变量/进程命令行/私钥。输出含已有业务名称和网络元数据，请私下提供。它检查资源、5 秒 vmstat 样本、监听端口、运行服务和定时器、Nginx 站点指令、证书元数据、Docker、备份目录和 UFW。安全组须在阿里云控制台单独核对。

还需补充业务高峰期间的 CPU、可用内存、磁盘 IO/剩余空间、连接量。一次快照不足以证明 2 核 4G 能承载既有业务。预发布须压测并观察 web/Worker/备份同时运行的峰值；构建建议放在同架构 Ubuntu CI，不挤占现有服务器资源。

## 2. 数据库选择与生成

- 默认仍为本地 PostgreSQL：`DATABASE_PROVIDER=postgresql`，原 `prisma/schema.prisma` 和迁移历史保留。
- SQLite：`DATABASE_PROVIDER=sqlite`，运行时 `DATABASE_URL=file:/var/lib/hushangyin/preview.sqlite`。
- MySQL：未来 `DATABASE_PROVIDER=mysql`，运行时 `DATABASE_URL` 指向沪上银独立数据库；本期不连接。
- `SQLITE_DATABASE_URL`、`MYSQL_DATABASE_URL` 供各自 Prisma Schema/迁移命令使用，必须与相应环境运行时 URL 对齐；不是自动双写。

```bash
npm ci
npm run db:generate:all
npm run db:validate:all
# 私有环境文件中选择唯一 provider 后：
node --env-file=/etc/hushangyin/app.env scripts/db-tool.mjs deploy sqlite
```

`prepare-db-schemas.mjs` 从 PostgreSQL 主 Schema 派生两个 Schema。业务字段改动后重新生成、检查差异，再为各连接器新增独立迁移；不能修改已应用的初始迁移。禁止 `migrate reset`、`db push --force-reset` 或跨连接器复用迁移目录。

SQLite/MySQL 将 PG `String[]` 转成 JSON 数组；JSON、枚举、日期、金额通过统一接口访问。SQLite 客户端初始化 WAL、外键、5 秒 busy_timeout、FULL synchronous；单连接池与数据库写锁表串行化交互式事务。Web 与单个 Worker 必须在同机本地磁盘使用**同一个绝对文件路径**，不能放 NFS/共享盘、public、.next 或临时目录。AI 网络请求保持在数据库写事务之外。

## 3. PostgreSQL → SQLite

1. 暂停**本项目** web、Worker、维护任务等所有写入，不影响其他站点。制作新加密备份，保留源实例；当前工具要求备份在 24 小时内。本地已有 `npm run backup:analytics`，只授权现有本地 PG。
2. 在私有目录创建迁移环境文件，权限 0600。填写下列键，不在终端参数或报告里粘贴数据库密码：

```ini
MIGRATION_FROM=postgresql
MIGRATION_TO=sqlite
MIGRATION_WRITES_FROZEN=true
MIGRATION_SOURCE_URL=由用户在私密文件填写原本地连接串
MIGRATION_TARGET_URL=file:/绝对私有路径/empty.sqlite
SOURCE_BACKUP_FILE=/绝对私有路径/本项目加密备份.dump.aes
MIGRATION_REPORT_FILE=/绝对私有路径/migration-result.json
DATABASE_PROVIDER=sqlite
DATABASE_URL=file:/绝对私有路径/empty.sqlite
SQLITE_DATABASE_URL=file:/绝对私有路径/empty.sqlite
LOCAL_TEST_MODE=true
```

3. Windows 本地路径使用 `file:D:/...`，Ubuntu 使用 `file:/var/lib/...`。先 `db-tool.mjs deploy sqlite` 创建空目标 Schema，再执行：

```bash
node --env-file=/私密路径/migration.env --import tsx scripts/migrate-database.ts
```

4. 工具拒绝非空目标，不覆盖/清空数据；PG 用只读 RepeatableRead 快照，目标单事务导入，补齐可空外键，再比较每张表所有标量字段的规范化摘要。保留 ID、密码哈希、原始时间戳、SQL NULL 与 JSON null。完整性/外键检查必须通过。
5. 本地副本含原账户和历史会话，仅用于私有验收。正式预发布需另行停写导出当前源库，将敏感文件加密传输到私有位置，确认 Linux 所有权/权限；**不能把 Windows node_modules 或本地 .env 打包上传**。
6. 原 PostgreSQL、备份和迁移报告继续保留。源库恢复写入后副本不会自动追平；最终切换必须重新冻结、备份、迁移到新的空库并核对，不得把陈旧测试副本直接当最新生产库。

## 4. Linux 发布结构与环境

建议 Node.js 24 LTS、同 CPU 架构 Ubuntu 构建，锁文件 `npm ci`，`npm run build`。构建环境的 SITE_URL 必须与目标一致，禁止把本地密钥/数据库打入产物。Next.js 静态 robots 等结果也要检查最终域名。

| 路径 | 用途/权限 |
|---|---|
| `/opt/hushangyin/releases/<版本>` | 独立发布产物；root 管理，服务用户只读 |
| `/opt/hushangyin/current`、`previous` | 当前/前一版本符号链接 |
| `/var/lib/hushangyin/` | SQLite/WAL/SHM；独立用户 0700，文件 0600 |
| `/var/cache/hushangyin/` | Next.js 缓存；独立用户 0700 |
| `/var/backups/hushangyin/` | 加密备份；独立用户 0700，不对 web 可见 |
| `/etc/hushangyin/` | 私密配置；root:服务组 0750，配置 0640 或更严 |

审计和授权完成后才可检查并执行 `prepare-private-paths.sh`。它遇到非本项目管理的已有目录、不同内容的同名 unit 会拒绝，不覆盖站点，不启动服务。系统中 Node 路径可能不是 `/usr/bin/node`，须按审计结果调整全部 unit 后再安装。

预发布以 `preview.env.example` 为模板写 `/etc/hushangyin/app.env`；生产计划用 `app.env.example`，默认关闭咨询、分析、AI 外发与 Worker。本地敏感配置和实际 AI Key 不作任何修改。

用户需填写/生成：

- `DATABASE_PROVIDER`、`DATABASE_URL`、`SQLITE_DATABASE_URL`、`SITE_URL`、`PORT=3120`；私有预发布 SITE_URL 为 SSH 隧道访问的 loopback origin。
- 独立随机 `SESSION_SECRET`、`RATE_LIMIT_SECRET`（各至少 32 字符）；不能复用开发值。切换新会话密钥并在**副本**撤销旧会话。
- `TRUST_PROXY` 仅在可信代理确实覆盖转发头时开启；直接隧道调试可关闭。
- `/etc/hushangyin/backup.env`：与 app.env **相同数据库路径**、备份目录、`BACKUP_ENCRYPTION_KEY_FILE`、保留天数；密钥是独立原始 32 字节文件 `/etc/hushangyin/backup.key`，不能打印。
- AI 配置由用户在 `/etc/hushangyin/app.env` 私下填写。生产外发和 Worker 需另行批准；迁移验收不使用真实 AI Key。
- 未来 MySQL URL、TLS CA/连接权限仅在另行授权后设置。

`deploy-preview.sh` 需要显式 `APPROVE_HSY_PREVIEW_DEPLOY=true` 和已有 Linux 发布目录，仅支持 loopback3120、预先迁移的私有 SQLite 和未启用生产开关。先在线备份、部署增量迁移、切换链接、重启**本项目 web**并检查健康；失败只回退代码链接，不自动恢复旧数据库。重复发布已有版本可重复执行，不覆盖其他业务。代码与迁移不向后兼容时须停写走人工恢复流程。

独立预发布访问可用 SSH 隧道 `3120:127.0.0.1:3120`。可选 Nginx 预览模板仅监听 loopback8086；若使用它，SITE_URL 必须同步为该隧道实际 origin，避免 CSRF 拒绝。不要将预发布监听改成公网。

systemd web/Worker 非 root，默认各 1024/384MiB JS heap，unit 有额外内存硬限制和只读文件系统。这些是候选值，**不是 4G 资源充分的证明**。Worker 默认关闭；所有 SQLite 写者必须使用本项目适配层，不能绕过事务锁表并发执行维护。

## 5. Nginx / 域名 / HTTPS

`deploy/nginx/` 是独立模板，不自动安装：HTTP 级限流区、安全 access log、反代 snippet、独立域名站点、私有预览站点。只加载新的独立文件，不能替换 nginx.conf 或已有 sites-enabled。

正式操作前：查精确/通配 server_name 冲突及已有 CDN；核对域名管理权、备案和业务资质；批准证书签发方式；确认 TLS 路径、续期和安全组。2026-11-03 的本地 DNS 查询显示该域名通过 `hushangyin.linhongtech.com.w.alikunlun.com` CNAME 返回 CDN 节点，非直接 A 到 ECS；不得未经确认改成直连。

只有授权后才安装独立配置，先 `nginx -t`；通过后方可讨论 reload，随后回归**全部原站点**。本轮未执行 nginx -t，未申请证书、改 DNS、安全组或打开公网。Nginx 模板支持 HTTP→HTTPS、TLS1.2/1.3、必要响应头、登录/咨询限流，拒绝私有数据库/备份路径。SQLite 从不由 Nginx 直接提供。

## 6. 在线备份、恢复与回滚

```bash
node --env-file=/etc/hushangyin/backup.env scripts/sqlite-backup.mjs
```

使用 Node24 SQLite online backup API 获取一致副本，完整性/外键检查后流式 AES-256-GCM 加密，并验证认证标签，写非敏感 manifest。临时明文仅在私有备份目录，退出清理。只清理本工具命名的过期备份，默认 30 天，允许 7–365 天。定时器为上海时间每日03:15加随机延迟。未在 ECS 启用。

恢复必须停本项目写者，**恢复到不存在的新文件**：在私密恢复 env 中设置 `BACKUP_FILE`、`BACKUP_ENCRYPTION_KEY_FILE`、`RESTORE_DATABASE_FILE`，然后执行 `sqlite-backup.mjs restore`。先验证 GCM 与数据库约束，失败删除本次创建的临时目标；拒绝覆盖现有数据库。验证完整业务、文件权限后，再人工切换 DATABASE_URL；原文件连同 WAL/SHM保持不动，不可对运行中的库直接复制单个主文件。

`rollback.sh` 仅显式授权回退本项目版本链接和 web 服务，不运行 down/reset，不恢复数据库。若切换后已有新咨询，不能直接回到旧 PG/旧备份而丢弃新写入；须停写、备份并核对增量。将备份密钥独立离线保管，否则加密备份无法恢复。

异地 OSS 仅有关闭的可选接口。必须先配置私有 bucket、最小权限 ossutil、加密/生命周期/地域、单独密钥保管及一次下载恢复演练；本轮未上传任何资料。

## 7. 未来 SQLite → RDS MySQL8

1. 另行批准，创建 `hushangyin_<环境>` **独立数据库**和最小权限应用账号，不能使用其他业务库。迁移账号 DDL 权限与运行账号权限分离，要求 TLS 验证和限制 ECS 来源。
2. 离线已准备 MySQL Schema/初始 DDL。使用 utf8mb4 与 `utf8mb4_0900_bin`，维持大小写敏感唯一键；JSON/日期/布尔/枚举/索引需在实际 RDS 补丁版本和 Serverless 条件下测试。会话 UTC、上海日统计由应用显式计算；当前代码无双写。
3. 在新的隔离 MySQL8 实例进行迁移、业务与并发测试。工具受 MYSQL_PRODUCTION_APPROVED 或隔离 loopback 测试门控；本轮不设置批准、不连接 RDS。
4. 冻结 SQLite 全部写者、制作新的已认证备份；配置迁移 from=sqlite、to=mysql、源/目标私密 URL，先 MySQL 专属 migrate deploy，再运行同一数据工具。目标非空拒绝；逐表全字段比较及业务外键验证后才切换环境。
5. 上线后发现故障先停写并保存 MySQL 新数据，不能简单切回陈旧 SQLite；切换前未有新写入时可回退源只读快照，已有增量必须迁移核对。保留源 SQLite 和备份直到批准结束回滚窗口。
