# 沪上银 V1.0.3 账号与 RBAC 开发验收报告

日期：2026-10-29（Asia/Shanghai）。项目：`D:\Codex\hushangyin-site`。

验收对象是本机实际运行的 `http://127.0.0.1:3000` Next.js 服务及原有 PostgreSQL 开发库，未部署生产。使用随机生成的合成员工、虚构手机号及咨询信息，不使用真实客户数据。

## 1. 原权限系统分析

- 原系统已有 iron-session 加密 HttpOnly Cookie、数据库不透明会话令牌哈希、Argon2id 密码、Origin 校验、持久化限流及审计日志，没有重建登录系统。
- 原角色只有 ADMIN / AGENT；ADMIN 读取全部线索，AGENT 按 assignedTo 隔离。没有部门、员工管理页面和首次改密流程。
- 原会话使用 updatedAt 判断失效；登录时间等普通更新容易和撤销条件耦合。本次改为显式 sessionVersion，并在每次请求读取最新账号状态与角色。
- 开发前重跑 V1.0.2 实际3000浏览器验收：咨询 POST 201、真实 PostgreSQL 线索及授权、后台详情、状态刷新持久化与未登录拦截均通过。首次尝试因本地私有凭据文件权限失败，随后在有权限的本地测试上下文执行通过，没有输出凭据。内置浏览器连接不可用，采用项目现有 Playwright + 本机 Edge，实际操作页面，没有使用 Mock。

## 2. 新增功能

1. 个人资料显示本人姓名、邮箱、角色、部门和本次改造后可靠记录的最近登录时间；提供原密码、新密码及确认输入。
2. 新密码至少12位，检查常见弱密码、重复字符和字母/非字母组合；验证原密码，拒绝重复密码。成功后递增会话版本、撤销全部会话，当前会话也需要重新登录。
3. 超级管理员创建、搜索、筛选、编辑、启停员工，分配四种固定角色；邮箱统一小写并由唯一索引约束。
4. 本地创建/重置凭据使用随机值、安全哈希、15分钟有效期。成功时只返回本次新生成的凭据，页面可以关闭清除；不读取或展示已有密码。首次登录只能查看本人资料、改密和登出，其余接口/页面被阻止。
5. 部门新增、名称编辑、启停。仍有有效员工或线索的部门不能停用；有负责线索的员工不能直接跨部门移动，必须先显式重新分配。
6. 停用、角色/资料变更、密码重置立即递增 sessionVersion 并删除会话；保留员工和历史线索。唯一有效超级管理员不能停用或降级；没有删除账号API。
7. 超级管理员在线索详情将线索分配给有效部门的主管/顾问，或取消分配；主管仅可在自己部门内重新分配已经属于该部门的线索。普通顾问不能分配。
8. 统一权限映射、服务端操作授权和 Prisma 查询范围同时生效；页面隐藏入口仅是交互配合。后台延续深蓝、品牌金和白色卡片，移动端表格内部滚动，不产生整页横向溢出。

## 4. 数据库迁移、保留与回滚

迁移前已生成项目私有忽略目录中的 PostgreSQL 自定义格式备份：`.local-postgres/backups/v103-before.dump`。备份包含客户数据和账号哈希，不上传或复制到报告。

- 原 ADMIN 枚举值重命名 SUPER_ADMIN；原 AGENT 重命名 FINANCING_ADVISOR，原账号ID与密码哈希保持不变。
- 增加 SALES_MANAGER、CONTENT_OPERATOR 枚举值。
- admin_users 增加 departmentId、mustChangePassword、sessionVersion、initialCredentialExpiresAt、lastLoginAt；admin_sessions 增加 sessionVersion。
- 新增 departments：id、唯一name、isActive、createdAt、updatedAt。
- leads 增加 departmentId；两个部门外键均为 Restrict，不级联删除客户/员工数据。增加部门/角色/状态和部门/线索时间索引。
- 迁移时仅递增原账号sessionVersion，使旧会话失效。没有清库、reset、覆盖密码或删除历史线索。
- 历史线索部门不推断，需超级管理员显式分配；未分配线索仅超级管理员可见。
- 所有账号/部门/分配变更使用数据库事务及统一事务级 advisory lock；唯一超级管理员检查和变更在同一锁内完成，避免并发绕过。

本机原有开发库和独立 `_test` 库均已安全迁移；重复 deploy 验证无待执行迁移。Schema验证通过，数据库与Prisma模型 diff 无差异。

数据保留依据正式 pg_dump 的一致快照核对：其中2条迁移前线索均存在，原管理员密码哈希逐一比对一致。初步JSON快照与V1.0.2基线测试并行，曾多记入1条随后由该测试finally清理的临时咨询；正式备份已在清理之后完成。已从备份提取ID建立权威基准，没有通过忽略未知业务记录掩盖数据丢失。

回滚预案：优先前向修复；原应用只认识旧角色枚举，不能直接接回新库。必要时先关闭写入，在隔离恢复库还原迁移前备份，核对账号、线索及迁移后增量，再经负责人批准切换配套应用。禁止在当前库直接DROP、强制重置或自动反向改枚举。实际备份恢复演练未执行。

## 8. 安全验证

- 后台页面、列表、详情、状态及分配API均服务端认证；未授权401、角色禁止403、范围外客户详情404。
- 根据数据库中的可信角色/部门构造Prisma条件；客户端不能指定其他部门来扩大范围；更新使用相同范围。
- 密码安全哈希；初始随机凭据短期有效、强制改密；重置不是显示旧密码。仅本地环回环境可交付一次性新凭据，正式环境未配置渠道时服务端拒绝创建/重置。
- 写操作Origin校验、HttpOnly/SameSite=Strict，HTTPS部署启用Secure/__Host-。本次HTTP环回环境未实测生产HTTPS属性。
- 会话令牌只存哈希；active/version/初始凭据到期检查每次执行；修改密码、停用和角色变更撤销全部会话。
- 登录：共享来源60次/15分钟、单邮箱5次/15分钟；支持多员工的同时保留单账户保护。改密5次、重置5次、重新认证30次、账号写入30次和分配30次，均为持久化15分钟窗口，成功操作也计数。
- 审计记录USER_CREATE/UPDATE/ENABLE/DISABLE、ROLE_CHANGE、PASSWORD_CHANGE/RESET、LEAD_ASSIGN、PERMISSION_DENIED及已有登录/读取/状态操作；metadata不含密码、Token或客户手机号。
- 不提供删除账户API；最后一个有效超级管理员的停用/降级保护在同一数据库锁内检查。
- 本轮未开放上传、GEO或AI功能，未修改真实客户数据，未部署生产。

## 10. 使用方法及下一阶段建议

- 员工管理：`http://127.0.0.1:3000/admin/settings/users/`。
- 个人资料：`http://127.0.0.1:3000/admin/settings/profile/`。
- 修改密码：个人资料页“修改密码”区块，或 `/admin/settings/profile/#password`。
- 创建员工：原超级管理员正常登录 → 部门管理先建立部门 → 员工管理“新增员工” → 填姓名/邮箱/角色/部门 → 验证本人密码 → 安全交付仅本次展示的15分钟凭据 → 员工首次登录改密。
- 分配角色：员工列表“编辑 / 重置” → 选择内置角色及部门 → 重新验证超级管理员密码保存；员工旧会话立即失效。
- 分配线索：超级管理员打开线索详情 → 选择有效部门的主管/顾问 → 重新验密保存；主管仅能在自己范围内重新分配。
- 本地启动仍为数据库就绪后 `npm start` 或 `npm run dev`，旧8080入口跳转实际3000。

必要下一步：正式上线前先接入受批准的账号邀请/重置交付、配置HTTPS和可信代理、完成加密备份恢复演练；再按已有权限边界规划GEO内容后台。不要在凭据交付尚未落实时直接对外开放本地测试流程。

最终验收状态：本地真实业务闭环及V1.0.3账号/RBAC功能验收通过。原管理员密码不变，2条备份基准线索全部保留，合成测试账号和业务数据已清理。未开放生产。
