## 1. 当前项目与兼容性分析

实际版本：Next.js 16.4.3、React 19.3.1、TypeScript 5.9.3、Prisma / Client 6.19.3；本机 Node 24.20.0。沿用 App Router、现有登录/RBAC、文章/FAQ 版本审核、持久化 Worker 和第一方归因系统。已阅读本地 Next.js 自托管指南，使用独立反代和服务端运行时配置。

原系统有 31 个业务模型。原 PostgreSQL Schema、8 个迁移及本地数据保留。不是替换连接字符串即可迁移：原代码使用 String 数组、JSON 路径过滤、PostgreSQL 原生类型、FTS、advisory lock、SKIP LOCKED、UPSERT 和原生聚合 SQL。

已实现按环境**单选数据库**的统一接口，不是双写或多主：

| 项目 | PostgreSQL | SQLite 首期目标 | MySQL8 后续目标 |
|---|---|---|---|
| Schema | 原文件保留 | 独立派生 Schema / 初始迁移 | 独立派生 Schema / 初始迁移 |
| String[] | 原生数组 | JSON 数组 | JSON 数组 |
| 日期 | 原 Timestamptz/Date | Prisma 日期映射 | DateTime(3)/Date；会话 UTC |
| JSON null | 原 SQL/JSON 语义 | 使用对应生成客户端 null 常量 | 同左，待实机验证 |
| 枚举/布尔/索引 | 不变 | 按实际 Prisma6.19 支持生成 | MySQL 枚举/布尔/索引 DDL |
| 检索 | 原 PostgreSQL FTS | 分类、关键词、中文子串回退 | 相同回退，后续实机优化 |
| 事务锁 | 原锁与领取逻辑 | 专用写锁表 + WAL 单写者 | 专用事务写锁表，待实机验证 |
| GEO 聚合 | 原 SQL 保留 | ORM + 显式上海日聚合 | 相同可移植路径，待实机验证 |

SQLite 新增 `deployment_write_lock` 技术表，不替代任何业务表；业务仍为31表。使用连接数1、WAL、foreign_keys=ON、busy_timeout=5000、synchronous=FULL。数组式 `$transaction([...])` 仍在同一数据库事务中逐项执行，未变成 Promise.all；JSON path、数组 has、大小写不敏感搜索和 skipDuplicates 做连接器适配。重试初始化可从连接故障恢复。

MySQL 使用 utf8mb4 / utf8mb4_0900_bin，避免默认大小写不敏感排序改变唯一键口径。Schema、客户端生成和 DDL 已准备，**未连接 MySQL/RDS、未实跑迁移**。实际 RDS8 补丁版本、JSON 默认值、排序规则、Serverless 唤醒、TLS 和事务行为仍待验证。
