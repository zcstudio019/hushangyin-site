因此：有权限且有效的账号1名，但该账号参与本版本；合格独立审核人0名。**这次原始账号的阻塞不是首次改密未完成，也不是旧权限缓存；防自审判断本身正确。** 完成授权后，缺乏可核验来源仍会单独阻止通过，分配审核人不能解除来源要求。

项目此前已有 `CONTENT_REVIEWER` 角色和正式员工更新接口，但员工页面的授权入口不够直接，分配页面没有逐个解释其他员工为何被排除，也未展示部门或提供明确刷新入口。本次补齐这些操作和诊断，不改作者、不补造历史提交人、不绕过独立审核。

实际登录本地原管理员，并比对个人资料API、数据库与FAQ页面得到上述结论。未使用角色改名或前端按钮替代服务端鉴权。

## 3. 账号首次激活机制

- 新员工仍经现有安全创建流程取得一次性、15分钟有效的本地初始凭据；本人首次登录被引导至个人资料改密。
- 未完成首次改密的账号不能成为候选审核人。未激活且初始凭据已过期时显示具体原因，沿用原安全重置交付流程，不自动重置。
- 已完成初始化的账号授权后不重新生成密码，不强制重复改密；即使历史初始凭据日期已经过去，也不影响其资格。
- 停用立即阻止登录、失效旧会话并失去审核资格。启用或重新授权后，按当前版本重新核验资格。
- 本次没有修改任何原员工密码或激活标志；测试只改虚构测试账号的初始密码。

生产邮件/凭据交付没有新增或开放。现有一次性本地凭据流程仅适用于本地虚构测试环境。

## 4. 候选人、版本与来源规则

统一策略 `review-policy.ts` 从数据库读取当前账号条件：启用、具有 `content.review`、完成首次改密，且未作为作者、编辑者、导入者、提交者或当前版本快照编辑者参与该版本。已有提交审计也用于判断参与者。

候选下拉显示“姓名（角色 · 部门）”。超级管理员可见未入选人员及全部适用原因：无审核权限、未激活/初始凭据过期、已停用、参与当前版本不能自审，并可进入员工配置。普通内容账号不获得该员工诊断列表。

“刷新审核人资格”重新读取服务端数据；所有分配和审核写入仍再次验证，不能依赖页面上的旧列表。分配绑定具体版本；修改、撤回、驳回等产生新版本时使旧分配失效并写审计。已分配版本须由指定且仍合格的审核人审批，超级管理员不能跳过；可以按正式流程重新分配。

审核中心新增“分配给我的待办”，筛选与翻页保留该范围；历史审核页不错误套用待办筛选说明。

FAQ答案为空时不能提交或批准。页面明确列出来源缺失项，提供引用填写区定位，以及锁定版本的“撤回审核 → 补充来源 → 保存 → 重新提交 → 重新分配”引导。来源填写继续复用现有编辑器，无重复存储。

引用须有真实标题、HTTPS网址和实际核验日期，可填适用截止日期、对应正文段落。格式和日期检查不能证明内容可靠；审核人必须人工判断来源支持实际答案，核对利率、政策、额度、承诺、隐私和金融宣传要求。审核清单强化这一职责，没有自动伪造引用或自动核验金融事实。

## 8. 用户操作入口

1. **授权内容审核员**：超级管理员访问 `http://127.0.0.1:3000/admin/settings/users/`，选择另一名独立人员，点击“配置审核权限”，再点“授予内容审核权限”，确认岗位替换并输入当前管理员密码保存。新建独立人员也可使用现有“新增员工”，角色选独立内容审核员。
2. **激活审核员**：新账号本人到 `/admin/login/` 登录，按引导到 `/admin/settings/profile/` 首次改密。已初始化的原员工只需授权后以原密码重新登录，不重复初始化。
3. **补充引用并分配**：在 `/admin/geo/faqs/` 打开目标FAQ；如缺来源，由作者先撤回审核，进入引用来源填写区，补真实资料并保存、重新提交。点击“刷新审核人资格”，在下拉选择姓名/角色/部门正确的独立人员，保存本版本分配。
4. **审核员查看待办**：登录后到 `http://127.0.0.1:3000/admin/geo/reviews/?view=pending&mine=true`，核对完整内容、引用和适用时间，完成清单后“审核通过”或填写原因“驳回”。
5. **正式发布**：具有发布权限的账号到 `http://127.0.0.1:3000/admin/geo/reviews/?view=ready`，进入已审核版本，点击“发布到官网”。独立内容审核员没有默认发布权限。
