# 第一方分析与来源归因运维说明

仅供当前模块化单体使用；未连接任何外部搜索或 AI 监测平台。

## 配置与启停

本地 `.env.local`：`ANALYTICS_ENABLED=true`，必须同时满足 `LOCAL_TEST_MODE=true` 和站点地址为本地3000端口。生产默认关闭：`ANALYTICS_PRODUCTION_APPROVED=false`。启用生产须另行完成真实隐私告知、适用要求、安全评估和用户授权，不能靠本地测试开关开放。

修改环境后重启 Next.js。新分析模块不依赖生成 Worker，也不向模型发送数据。原生成 Worker 使用原启动命令，不应为统计重启或消耗生成队列。

## 浏览与归因

只统计文章详情及 FAQ 详情，不统计列表、预览、后台和未公开内容。主动点击“同意本次匿名分析”才签发30分钟匿名标记，保存在当前窗口的 sessionStorage，不设置分析 Cookie，不采集设备指纹。用户可停止，拒绝不影响咨询。

PV：授权后的浏览事件。访问次数：上海日期×内容×短期随机会话去重，不代表自然人。咨询点击：授权后的咨询链接点击。成功咨询：原线索事务成功提交且来源经过校验。转化率：至少成功咨询一次的授权匿名访问/授权匿名访问，30分钟窗口；同一会话/内容每天仅一个转化。转化按来源访问日统计，不是全量线索数/PV；少于20个访问标记低样本。

文章与问答的同源咨询点击取得短期签名来源上下文。服务端在提交时再次验证内容已公开。无凭证的旧文章入口只标记“客户端声明、校验公开内容”，不得充当站内点击证明。过期或验签失败为未知来源，格式非法请求被拒绝；直接访问不归到GEO。UTM仅接受40字符以内的营销代码，拒绝手机号及明显凭据格式；渠道始终是可伪造的客户端线索，不是外部平台证明。没有采集数据显示“暂无数据”。匿名标记按上海日期脱敏，跨午夜不拼接，可能低估跨日的分析转化；真实咨询及内容来源照常保存。

## 保留与定时维护

`npm run analytics:maintenance` 在本地允许执行；生产须单独设置 `ANALYTICS_MAINTENANCE_APPROVED=true`。只处理分析数据，不删除 leads、customers、consents、员工、FAQ、文章和审核记录。

| 数据 | 保存期限 |
| --- | --- |
| 原始PV/点击及去重事件 | 30天 |
| 来源记录与匿名会话的关联 | 30天后解除 |
| 线索来源归因附表 | 180天 |
| 按日聚合 | 365天 |
| 人工导入的平台表现数据 | 730天 |
| 同步/导入任务与人工可见性观察 | 365天 |

聚合在事件事务内即时更新，维护无需重复聚合。上线前须由运维每天安排一次维护命令；本次未修改 Windows 全局任务计划，未安装常驻调度器。审计日志沿用现有系统留存管理。线索本身继续遵循原授权与业务留存政策。

## 平台与人工观察

入口 `/admin/geo/analytics/search/`。超级管理员配置平台属性，再预览并确认 CSV。Google 只支持官方搜索效果报告的**日期维度、单站点、网站搜索**导出：Date/Clicks/Impressions/CTR/Position，或对应中文日期/点击次数/展示次数/点击率/排名。不能混入网页、查询、对比或多搜索类型。1MB、1000行。相同日期数值相同跳过；不同须明确确认替换，不做累加；失败整批回滚。模板只有表头，不附伪造曝光数据。

Google 原导出日期不擅自改成上海日期；不要直接与第一方上海日期日表相加。用户未提供实际平台文件，本次以等价字段夹具验证。百度及 Bing 需要真实导出样例才能适配；当前明确拒绝，不伪装成功。自动同步操作持久化为“阻塞：未授权/未接入”，没有外部请求、没有曝光数据。

官方口径参考：[Google导出报告](https://support.google.com/webmasters/answer/12919797?hl=en)、[搜索效果指标](https://support.google.com/webmasters/answer/7576553?hl=en)。人工导入不等于完成 API 授权。

入口 `/admin/geo/visibility/`。只记录人工实际验证的公开结果与证据，分别标记品牌提及、官网链接引用及推荐；AI来访仅为站内报告中的渠道线索。人工记录是抽样，不代表排名，不能把软件测试夹具当成真实AI搜索结果录入。

## 备份与回滚

迁移：`npm run db:deploy`，禁止 reset/db push --force-reset。新增迁移 `202611020001_geo_analytics`，不删除原表数据。

本地迁移前 `npm run backup:analytics` 使用 pg_dump 自定义格式并直接 AES-256-GCM 加密，私钥派生材料仍在现有受保护本地配置中，不输出。密文备份位于忽略的 `.local-postgres/backups/`。认证和PGDMP归档头已验证；完整恢复演练尚未执行。不可把“备份存在”当成恢复演练通过。

回滚优先关闭采集开关并回退应用，保留新增表、归因与原业务数据。需恢复备份时，先在独立数据库解密验证并使用匹配 PostgreSQL 工具执行恢复演练，核对迁移前后新增的客户线索，禁止直接用旧备份覆盖当前业务库。生产另需加密备份、独立密钥保管、访问控制和恢复演练。

## 验证与清理

`npm run test:analytics` 使用独立 `_test` 数据库；包含幂等迁移、事务、去重、导入冲突和保留策略。`npm run test:analytics:browser` 使用实际3000服务和本地业务库，以现有授权接口创建临时运营/独立审核员及合成内容，通过真实Edge完成页面操作。仅按本次生成ID清理关联事件、聚合、线索、授权、版本、审核、账号及测试审计，不按标题模糊清理，不清空任何表。

不要频繁连续重跑浏览器验收：原登录保护每账号15分钟5次，咨询共享保护15分钟10次。触发时等自然到期，不能清空限速桶。验收结果和截图只含合成资料，位于被忽略的 `test-results/analytics/`。
