## 1. 根因与原实现审计

- `src/components/forms/GeoForms.tsx` 的 QuestionImport 只处理CSV，界面直接展示英文表头和枚举，没有Markdown解析、逐条预览或确认步骤。

- `/admin/geo/faqs/` 原先没有批量导入入口；FAQ使用ContentStatus，问题库使用QuestionStatus，不能共用同一套状态值。
- 分类数组、意图及大部分状态本来已有中文映射，但PLANNED/ANSWERED文案与新资料不一致，审核记录直接显示APPROVED/REJECTED；未知状态回退显示原英文值。
- 原文件还使用“贷款申请准备”，与当前“银行贷款申请条件”含义不同。已明确补充前者为合法分类，保留两者，不改写原资料分类。
- 原RBAC、同源保护、Argon2id会话体系、GEO事务锁、SafeMarkdown及咨询入库流程可复用，没有重建网站、数据库或认证系统。

## 3. 字段及状态映射

内部字段、API键、数据库枚举保持英文；只在录入/导入与视图边界做转换。映射集中管理，用户正文不会被任意翻译或改写。

| 内部值 | 中文显示 |
| --- | --- |
| question / category / keywords | 融资问题 / 问题分类 / 关键词 |
| intent / priority / status | 搜索意图 / 优先级 / 状态（问题上下文为问题状态） |
| AWARENESS / COMPARISON | 认知型 / 比较型 |
| DECISION / PREPARATION | 决策型 / 申请准备型 |
| 问题OPEN / PLANNED | 待规划 / 已规划 |
| 问题ANSWERED / ARCHIVED | 已解答 / 已归档 |
| 内容DRAFT / IN_REVIEW | 草稿 / 待审核 |
| 内容APPROVED / PUBLISHED / ARCHIVED | 已审核 / 已发布 / 已下线 |
| 审核决定APPROVED / REJECTED | 审核通过 / 退回修改 |

没有新增或臆造OFFLINE状态；内容下线实际使用ARCHIVED，问题归档虽然也叫ARCHIVED，但按不同模型显示。

- 问题默认AWARENESS、优先级3、OPEN；已解答必须关联文章，导入文件不提供文章关联时会明确报错，提示先以已规划导入后关联文章。
- FAQ默认IN_REVIEW，可显式DRAFT。PUBLISHED、APPROVED、ARCHIVED等状态请求一律安全转为DRAFT并在预览中说明，不能通过导入完成审核/发布。
- 旧英文CSV枚举和原“创作中/已关联解答”显示词可兼容接收；新模板、筛选和列表统一显示“已规划/已解答”。
- FAQ导入不会创建审核记录或公开快照，isLive始终false；需要补齐可靠引用时撤回审核、编辑后重提。

## 4. 解析格式与上限

### 问题

```markdown
# 文档标题
## Q001｜上海企业申请经营贷款通常需要准备哪些资料？
- 分类：企业经营贷款
- 关键词：上海企业贷款、经营贷、申请资料
- 搜索意图：申请准备型
- 优先级：1
- 状态：待规划
- 来源：内部选题整理
```

一级标题及“字段说明”等非记录小节不构成问题。只有 `## Q数字｜问题` 开始记录，也兼容半角竖线。属性顺序可变化，冒号支持半角/全角，关键词支持顿号、逗号及旧CSV竖线。问题、分类必填；其他字段用既有安全默认值。未知/重复属性明确报错，不静默丢弃。

### FAQ

```markdown
## F001｜什么是企业经营贷？
- 分类：企业经营贷款
- 状态：待审核

### 答案

在这里填写需要人工核验的答案。

- 保留必要列表。
- 具体条件以真实金融机构规定为准。
```

`## F数字｜问题` 开始记录。`### 答案` 以下到下一条FAQ记录前保留答案段落、列表、标题、引用、表格等Markdown结构；代码块中的类似记录标题不会误拆。缺失或空答案、未闭合代码块、无效分类/状态均提示记录编号和行号。

每次最多100条，原始UTF-8文本最多1,048,576字节；JSON请求体最多2,105,344字节。客户端检查扩展名、大小并严格UTF-8解码，服务端独立检查内容字节、条数、字段长度和模式。问题最长300字符、关键词最多15个且各40字符、答案最长20,000字符、来源最多600字符。

来源不作为事实核验背书。原文编号、来源、导入人、时间及格式保存在原表importMetadata，可在后台详情看到；编号不替代随机数据库主键。原始文件本身不会上传存入public或服务器文件目录。

## 5. 预览、去重与事务策略

1. 文件与文本粘贴择一提交，不把两个输入隐式合并；文件类型与所选入口必须一致，不自动猜测或切换解析器。
2. 服务端返回识别、有效、重复、待新增、错误数量，以及逐条编号/行号、拟处理动作、错误、来源和警告。FAQ可展开安全答案预览。
3. 有错误则不生成确认凭证，确认按钮禁用；全部校验通过后，用户还需勾选确认。
4. 预览凭证有效10分钟，HMAC绑定当前账号、内容摘要、类型、格式和到期时间；内容被改或换账号不能复用。服务端确认时重新解析，不信任客户端预览结果。
5. 写入持有原GEO事务级advisory lock，并再次检查最新账号、会话版本、权限和已有重复项；整个新增与审计在同一事务。
6. 去重键只用于比较：问题文字NFKC规范化、统一空白和大小写；存储仍保留原问题文字，不按Q/F编号去重。沿用现有“问题文字全库唯一”规则，分类不同也跳过同问题，并明确说明不会覆盖分类/答案/来源。
7. 重复项默认跳过，文档内和数据库已有重复都报告；所有其他错误导致整批拒绝，不能部分保存。两个并发相同确认请求已实测只有一份新增。
8. 返回successCount、skippedCount、failedCount、逐条rows/errors、createdIds、审计reference及原count兼容字段。业务校验失败通过受控error.details报告；鉴权/限流/超体积仍沿用原统一错误结构，不泄漏数据库信息。

接口：

| 接口 | 协议 |
| --- | --- |
| POST `/api/admin/geo/questions/import/` | 原CSV及新Markdown/CSV预览确认 |
| POST `/api/admin/geo/faqs/import/` | FAQ Markdown预览确认 |

新请求使用 `{format,text,mode}`，mode为preview时200且不写业务行；commit时需confirmed及confirmationToken，完成后201。内部英文契约仅出现在代码/API，不在界面说明中直接展示。

兼容说明：原 `{csv}` 请求仍可直接提交，字段和count保留；显式API调用仍执行完整校验、权限和事务。**重复策略按本次要求改变：从V1.5.1整批409拒绝，改为201并返回跳过数，不自动覆盖。** 原GEO回归已按这一有意变化更新；中文和原英文CSV模板均实测可用。

## 10. 使用入口、模板和未验证项

入口：

- 问题库：`http://127.0.0.1:3000/admin/geo/questions/`
- 常见问答：`http://127.0.0.1:3000/admin/geo/faqs/`

模板：

- 问题Markdown：`public/templates/geo-questions.md`，下载 `/templates/geo-questions.md`
- FAQ Markdown：`public/templates/geo-faqs.md`，下载 `/templates/geo-faqs.md`
- 中文CSV：`public/templates/geo-questions.csv`，下载 `/templates/geo-questions.csv`

操作：内容运营或超级管理员登录 → 展开对应Markdown导入 → 选择原文件或粘贴 → 解析预览 → 核对条数、分类、状态及来源 → 勾选确认 → 导入 → 刷新/分页查看。若预览超过10分钟或修改了内容，需重新预览。

尚未执行/边界：

1. 原始100题、60组未实际入库，这是用户要求，不是验收阻塞；原文件内容的业务、金融事实和来源可靠性未由本次开发核验。
2. 没有生产部署、生产HTTPS/代理测试、备份恢复演练、跨浏览器完整矩阵或高并发压测。没有停止原数据库作故障注入。
3. 自动化通过受控合成内容模拟操作，不替代正式人工审核；图片及敏感文件接收能力仍未开放。
4. 导入按原有全库问题文字唯一规则跳过，暂不支持覆盖、合并或导入时关联文章；已解答需后续关联文章。
5. 规范化比对读取现有问题标题与分类，未建立新的归一化唯一索引。当前100条批次已验证；内容量显著增长后可在保留数据、分析冲突前提下做索引优化，不得清库解决重复。
6. 限流及防重辅助记录按有效期逻辑过期，不通过清空共享安全桶绕过测试。用户原文件没有复制到public或报告正文。

最终状态：**V1.5.2 本地验收通过，可由用户自行确认导入两份原资料。**
