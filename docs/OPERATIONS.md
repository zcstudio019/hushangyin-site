# V1.0 运行、安全和回滚

## V1.5.2 Markdown导入与中文显示

问题库 `/admin/geo/questions/` 支持Markdown和CSV，常见问答 `/admin/geo/faqs/` 支持Markdown。两者共用预览/确认组件：选文件或粘贴择一输入 → 解析预览 → 修正全部错误 → 勾选确认 → 导入。不要把预览成功当作已经写库。页面提供中文示例和下载模板；旧英文CSV表头与枚举仍可接收，内部API字段与数据库枚举不改名。

记录标题分别为 `## Q001｜问题`、`## F001｜问题`；问答必须有 `### 答案`。一级文档标题和问题库字段说明不是记录。分类必填；问题默认认知型、优先级3、待规划。问答默认待审核或显式草稿；请求已发布/已审核等状态只会保存成草稿并给出提示，不会自动发布。需要补充可靠引用时先撤回审核、编辑后再提交，继续执行独立人工审核。

每次最多100条，文件/文本UTF-8字节上限1MB，JSON请求体另有限制。CSV中有逗号的单元格需加双引号；关键词可用顿号分隔。脚本、事件属性和不可信HTML/链接会被拒绝，原问题文字和答案段落不随意改写。

来源、原文编号、导入人和时间保存到questions/faqs的importMetadata；原文编号不是数据库主键。按规范化问题文字与已有全库唯一规则去重，分类不同也跳过同问题，绝不覆盖既有答案/来源。确认写入时持有原GEO事务锁，再次检查账号权限及数据库重复情况；任何校验错误均不写入部分业务行。成功响应包含新增、跳过、失败数和逐条报告，重复提交可安全跳过。

新预览接口生成10分钟有效、绑定账号和内容的凭证；确认时服务端重新解析并检查凭证/勾选。预览每人60次/15分钟、确认30次/15分钟，沿用原内容写入限额。原`{csv}`接口保留直接提交兼容，同样执行服务端校验、事务和重复跳过，返回原count及新增报告字段。与V1.5.1不同，重复项不再整批409报错，而是201并报告跳过数量。

升级先私有备份，再 `npm run db:deploy`、`npm run db:generate`、`npm run build`，重启 `npm start`。迁移`202610290003_geo_import_metadata`仅为两张原表新增可空JSON字段，不删表、不改状态枚举、不更改已有正文。生产未修改。本机备份在忽略目录 `.local-postgres/backups/v152-before.dump`。

回滚优先前向修复；必须回退时先关闭新导入入口并使用对应旧构建，保留新增JSON列及已导入的来源记录，不执行自动DROP或重置。数据恢复须先在隔离库验证备份，不能直接覆盖当前业务库。

`npm run test:geo-import` 使用实际3000、原PostgreSQL和本机Edge验证；合成100题/60组写库并清理，用户两份原资料只做干运行，不自动入库。原资料默认从Downloads读取；若不存在，结果必须记录未验证原文件。测试需要本地私有管理员配置、迁移前基准和现有浏览器运行时，不打印凭据。`npm run test:geo` 已适配CSV预览确认及默认跳过规则。不要对生产运行这些本地合成测试。

## V1.5.1 GEO 内容运营

本地入口 `/admin/geo/`，下设 `/articles/`、`/questions/`、`/faqs/`。延用账号和权限：CONTENT_OPERATOR 可读写内容，SUPER_ADMIN 可审核与发布，销售角色不能访问内容管理，内容运营不能读取客户线索。审核人必须不同于当前版本最后编辑人；超级管理员编辑的稿件也需要另一位具有审核权限的人员复核。

迁移流程：先对现有库执行私有备份，再 `npm run db:deploy`、`npm run db:generate`、`npm run geo:migrate`、`npm run build`，最后重启 `npm start`。本机已执行。`geo:migrate` 只把代码仓库中原有4篇已公开文章保留到数据库，不生成新金融内容，不伪造作者、发布日期或审核记录。重复执行跳过已保留文章；对有编辑冲突或已经下线的内容拒绝覆盖。原网址 `/insights/[slug]/` 保持稳定，`/knowledge/` 308跳转到现有入口。

操作流程：问题规划/CSV导入 → 文章或FAQ保存草稿 → 认证预览 → 提交审核 → 另一审核人逐项核实引用及适用时间、审批承诺、银行关系、案例、宣传和隐私 → 审核通过 → 授权发布。新内容至少一项HTTPS引用、有效核验日期；审核和发布均重查来源有效时间。后台不能通过隐藏按钮代替服务端权限。审核通过后的编辑会生成新草稿，需重新审核；线上快照保留至新版本通过并发布。恢复文章历史版本也生成新草稿，不直接发布。

Markdown仅通过React安全元素渲染，不支持原始HTML执行。H1由标题字段生成，正文工具支持H2/H3、段落、列表、表格、引用、链接和已审核本地位图引用。图片上传没有接口，保持禁用。CSV只接收认证员工的问题文本；V1.5.2上限为1MB、100条，重复项跳过，其他错误拒绝整批，执行事务导入，不将文件存至public。引用来源的可信性仍需真实人工核验，程序不会把任意HTTPS地址当作事实背书。

文章和FAQ下线后不再公开；文章URL返回404，动态Sitemap下一次请求即移除。未公开的草稿、审核记录和预览需要认证。不要运行旧静态服务器或旧生成器来发布内容；旧静态逻辑无法反映数据库的下线状态。

文章CTA只带非敏感文章ID进入咨询页。既有咨询API校验来源文章仍在线，规范化来源路径，仅接收 utm_source/utm_medium/utm_campaign 三项长度受限的ASCII标记，拒绝手机号样式值及未知字段，和线索/授权在原事务保存。不把客户手机号、征信信息放到URL或日志。来源参数是营销上下文，不是身份凭据，也不等于不可伪造的归因证明。

`npm run test:geo` 对实际3000 + 现有PostgreSQL + Edge执行完整流程。仅限本地合成系统文章及虚构咨询，测试结束按精确ID与合成标记清理，不删除原有账号、部门、线索或原文章。需要既有本地私有管理员配置、迁移前基准文件及现有浏览器运行时；这些文件不提交。完整结果在忽略目录 `test-results/v151/`。`npm run test:rbac`、`npm test` 和 `npm run test:browser` 继续回归原功能。不要并发执行会发布/下线文章的GEO测试和依赖固定Sitemap条数的公开页回归。

V1.5.1回滚：优先前向修复。停写后在隔离恢复库演练 `.local-postgres/backups/v151-before.dump`，对账迁移后的新文章/版本/来源关联，再批准切换。禁止自动DROP、reset或清空当前库。旧版本使用静态知识文章，可能重新暴露已下线内容，不能直接回退后开放知识入口。此轮没有执行备份恢复或生产部署。

## V1.0.3 账号、部门与权限

先备份数据库，再执行 `npm run db:deploy`、`npm run db:generate`、`npm run build`，最后重启 `npm start`。迁移将 ADMIN/AGENT 分别平滑改名为 SUPER_ADMIN/FINANCING_ADVISOR，保留原密码和线索；旧会话一次性失效，需要重新登录。迁移不重置数据库。

个人资料和改密：`/admin/settings/profile/`；员工：`/admin/settings/users/`；部门：`/admin/settings/departments/`；固定角色说明：`/admin/settings/roles/`。超级管理员先新增部门，再新增员工并选择角色和部门。主管/顾问必须有有效部门。敏感管理操作每次验证当前超级管理员密码。

新增和重置员工凭据仅在 LOCAL_TEST_MODE=true 且 SITE_URL 为环回地址时可用。随机凭据仅在成功响应页面显示一次，15分钟有效，关闭后不再显示，首次登录必须修改密码。不要将凭据放入截图、日志或报告。正式环境缺少经批准的交付渠道时服务端拒绝创建/重置，不允许直接沿用本地交付方式上线。忘记密码由另一位有效超级管理员重新认证后重置，不提供旧密码查看；尚无邮件自助恢复或唯一管理员失联后的自助恢复功能。

改密、停用、资料/角色变更都会递增 sessionVersion 并撤销现有会话。改密后当前会话也需重新登录。停用不删除线索，超级管理员在详情页重新分配。已有未设置部门的历史分配由超级管理员显式重新分配，迁移不猜测部门。未分配线索仅超级管理员可见。

`npm run test:rbac` 对实际3000端口执行 PostgreSQL + Edge 测试，仅允许本地虚构数据环境。测试需要现有本地管理员的私有配置及迁移前备份基准（位于忽略的 `.local-postgres/backups/`）；使用随机测试账号，finally按精确ID和合成标记清理，不删除原账号和线索。当前工程环境使用现成 Playwright 运行时，其他机器应通过 PLAYWRIGHT_PATH 和 BROWSER_PATH 指定已有安装。不要将这一测试直接用于生产。

## 环境和启动

Node.js 22.12+（本次开发 Node 24），PostgreSQL 16+；同一 Next.js 应用承载官网、后台和 API。使用 npm 锁文件，`npm ci` 安装，禁止将开发数据接入生产数据库。

1. 复制 `.env.example` 为 `.env`，设置本地 `SITE_URL=http://127.0.0.1:3000` 和独立 PostgreSQL `DATABASE_URL`。
2. 分别用 `node -e "console.log(require('crypto').randomBytes(48).toString('base64url'))"` 生成 SESSION_SECRET、RATE_LIMIT_SECRET，存入密钥管理器/本地环境文件，不提交 Git。
3. `npm run db:generate`、`npm run db:validate`、`npm run db:deploy`。
4. 首次管理员：在私有环境中设置 ADMIN_EMAIL、ADMIN_NAME、ADMIN_PASSWORD（至少16字符），执行 `npm run admin:create`，然后清除初始化密码环境变量。重复执行不会覆盖已有账户或重置密码。脚本不会输出凭据；不要把密码放在命令行参数、截图或共享日志中。
5. 可选 `npm run db:seed`：仅新增缺失的现有文章草稿，绝不写入客户测试数据或覆盖运营内容。
6. `npm run dev`，访问官网 `/`、后台 `/admin/`。
7. 咨询开关默认为关闭。补齐 `/privacy/` 真实个人信息处理者、联系方式、权利申请渠道和留存期限，验证数据库、安全措施后，才能在部署环境设置 `CONSULTATIONS_ENABLED=true`。数据库未配置、未启用或故障时 API 不返回伪成功。

## 数据库模型

基础业务表：customers、leads、admin_users、audit_logs、consents、articles、faqs、loan_products。V1.0.3增加departments；V1.5.1增加geo_questions、article_versions、article_relations、content_reviews并扩展原articles/faqs/leads。另有admin_sessions、rate_limit_buckets、submission_guards三张安全辅助表。字段、外键和索引见 `prisma/schema.prisma`。姓名/手机号只存入必要业务记录，不存入普通日志或审计metadata。客户档案不会仅凭同手机号自动合并，避免误关联。

会话仅在 Cookie 存放加密不透明令牌，数据库存其 SHA-256，8小时到期；每次服务端核实管理员 isActive、sessionVersion 和最新角色。密码 Argon2id。注销删除数据库会话。SUPER_ADMIN 全部线索，SALES_MANAGER 有效部门中已明确分配的线索，FINANCING_ADVISOR 仅 assignedTo=自身，CONTENT_OPERATOR 不可读写客户线索。账号/分配通过受保护页面和API操作并记录审计。

所有写请求必须带与 SITE_URL 一致的 Origin，并拒绝 cross-site 请求。生产 HTTPS Cookie 使用 __Host- 前缀、Secure、HttpOnly、SameSite=Strict、Path=/。本地环回 HTTP 测试 Cookie 允许非 Secure，不能用于对外部署。

频率限制使用 PostgreSQL 原子计数，不依赖单进程内存；默认共享来源桶，只有反向代理覆盖（而非透传）x-forwarded-for 时才启用 TRUST_PROXY=true。咨询每来源15分钟10次；登录每来源60次、每邮箱5次。V1.0.3 为多员工保留共享来源容量，单邮箱限额不变。重新认证30次、密码修改5次、密码重置5次、账号写操作30次、分配30次，窗口均15分钟。成功操作也计数；自动化测试应隔离账号，不能清空共享安全桶绕过限流。相同电话/客户类型/金额5分钟内通过事务防重复，指纹为带密钥 HMAC，不保存明文 IP。开通前按流量调整限额，并在边缘代理添加连接与请求速率限制。

## 生产构建与部署准备

`npm run typecheck`、`npm run lint`、`npm test`、`npm run build`、`npm start`。Next独立监听本机地址，生产使用可信HTTPS反向代理；容器绑定地址需按托管方案调整脚本，不直接暴露数据库。真实SITE_URL必须通过环境提供；example.com被拒绝。环回URL仅用于本地生产构建测试。文章发布/下线自动影响动态Sitemap，无需构建；变更站点URL仍应保持构建与运行环境一致，并重新构建依赖站点配置的robots等内容。

部署前：完整 PostgreSQL 备份、在 staging 执行迁移、人工审核 SQL，再执行 `prisma migrate deploy`。禁止 `db push --accept-data-loss`、`migrate reset` 或自动清库。使用单独低权限应用角色；迁移账户与运行账户分离，限制网络，启用证书验证的数据库 TLS。数据库磁盘及备份必须启用平台提供的加密（KMS/受控密钥），此仓库不能替代部署平台的存储加密；未验证加密和恢复前不接收真实客户资料。应用当前不做字段级加密，若威胁模型要求数据库管理员也无法读取，下一阶段引入 KMS 信封加密，不能误称已具备。

API 路由为 `/api/consultations/`，后台 API 为 `/api/admin/login/`、`logout/`、`leads/`、`leads/[id]/`（GET/PATCH）。不带尾斜杠自动规范化，POST 保留方法。客户资料路由不缓存、服务端鉴权；后台 noindex 及 robots 禁止抓取不是鉴权替代。

## 留存、备份与恢复

建议默认未转化线索最后更新180天后由负责人审核删除/匿名化；客户、授权、审计的最终期限应依据真实业务与适用要求确定并公示，不直接编写自动清除任务。删除个人数据时同步处理客户、线索和备注，保留必要的脱敏授权/审计凭证；外键 SetNull 防止删除身份记录时误级联删除审计。过期会话、限流桶、防重指纹可按 expiresAt 清理，仅由受控作业执行并记录计数；不要将原始键值输出到日志。

使用 pg_dump 自定义格式每日备份、托管 PITR/WAL；备份加密、限制访问、密钥分离并定义到期销毁。恢复到隔离数据库，校验迁移版本、行数、关系和应用读写，再决定切换。每季度演练恢复并记录 RPO/RTO。数据库 URL/密码通过受控环境传递，避免命令行或共享日志暴露。

## V1.5.3 内容创作执行器与运行边界

本机按用户决定不配置模型密钥。真实 AI 生成与发布验收未完成；已有官网咨询与员工权限仍使用原服务。不要把测试适配器的结果当成模型效果验收。

### 初始化与启动

1. 对既有 PostgreSQL 先做受控 `pg_dump` 自定义格式备份；在隔离恢复库验证后执行 `npm run db:deploy`。本轮迁移为 `202610290004_ai_generation`，只新增表、可空列、索引和历史问题关联，不清空原表。
2. `npm run generation:seed`：幂等创建默认写作模板，不覆盖现有模板，也不生成或核验外部资料。
3. `npm start` 或 `npm run dev`：网站进程。
4. 另一个终端运行 `npm run worker:geo`：独立数据库任务执行器。生产准备时使用宿主机进程管理器，保持运行、优雅退出和失败重启；不是在 HTTP 请求结束后启动的临时 Promise。当前没有启用生产环境。

未来具备用户批准与安全条件后，由受控服务端环境配置 `OPENAI_API_KEY`、`AI_MODEL`、`AI_PROVIDER`、`AI_BASE_URL`。同时显式批准 `AI_EXTERNAL_TRANSMISSION_APPROVED=true` 与 `AI_GENERATION_ENABLED=true` 才允许创建任务。本次不写入这些值、不创建密钥。任何密钥不得使用 NEXT_PUBLIC_ 前缀、粘贴到页面或提交到仓库。模型名称不设默认；`AI_MAX_OUTPUT_TOKENS` 限1000至16000，`AI_TIMEOUT_MS` 限5至120秒。兼容接口是否完整支持严格JSON格式，须在获准接入后真实验证。

### 运营流程

内容运营进入 `/admin/geo/generation/`，选择问题、核对已审核知识、设置写作要求、确认资料不含个人信息，再创建任务。任务列表 `/admin/geo/generation/tasks/`。超级管理员在 `/admin/geo/generation/templates/` 维护版本化模板与人工核验的公开参考资料。系统不自动抓取外部网址，不能自动证明金融事实。

默认队列每个任务最多执行3次，执行器使用 PostgreSQL 行锁跳过已领取任务、持久化租约和超时。断电或进程丢失后，租约到期才能安全重试。取消或过期租约不能产生迟到草稿。供应商可能已接收超时请求并计费；本地不重复保存文章不等于供应商不会产生重试成本。定价可选配置按百万词元美元单价，未知时显示不可估算，不填虚构的0成本。

生成结果原子保存到原 articles 及版本表，状态只能为草稿。对应问题先为已规划；经独立人工审核及授权发布后变成已解答。最后一个有效解答下线后回到已规划，历史关联仍保留。已有线上快照在编辑草稿时继续有效。

生成文章在既有编辑器内使用分组引用输入，分别填写标题、HTTPS网址、核验日期、可选截止日期与对应正文原段落；段落支持换行和表格分隔符。来源网址、日期及段落必须匹配参考资料目录与当前正文。原人工文章逐行四项格式保持兼容（也可附可选正文段落）。规则检查中的“必须修复”会阻止提交审核、通过和发布；人工核实提示必须由独立审核人结合真实来源处理。不能以规则通过或AI自评替代人工审核。

### 权限、日志与留存

沿用原会话和 RBAC：内容运营有 `generation.create`，只能枚举和操作本人任务；超级管理员有 `generation.manage`，管理模板、参考资料与全部任务。销售及顾问默认无内容生成权限。所有写API校验同源、权限、输入和请求大小。生成每人每小时5次；原内容写操作限制继续生效。普通运行日志不输出提示词、客户信息、密钥或供应商错误正文。

任务快照仅保留选题知识、人工补充和模板，用于溯源，不读取客户或线索表。机器识别个人信息有漏检与误报，人工不得输入征信、流水、手机号等客户资料。上线前须由负责人确定供应商数据政策、外发授权、任务输入/输出/调用日志的保存期限和访问审计，并设置受控归档；本次不自动删除历史数据。审计操作仅存ID、动作和必要计数/版本信息。

### 验证与回滚

- `npm run test:generation`：仅本机独立 `_test` 库，真实数据库+固定输出适配器，测试队列、超时、重试、草稿事务、审核和状态回写，不发起模型请求。
- `npm run test:generation:browser`：实际3000服务和Edge，验证选题、知识排除、无密钥503、权限与四视口。需要现有本地数据库环境；脚本创建并清理随机凭据的合成验收账号，不修改原管理员，禁止复制凭据到测试报告。
- `node --env-file=.env tests/v153/preserve.cjs`：对本轮迁移前私有快照做原数据核对，仅输出统计。

本轮备份 `.local-postgres/backups/v153-before.dump` 与私有核对快照不对外分享。回退时先停止执行器、关闭生成开关，再切回V1.5.2应用；新增表和列可留存，不自动DROP。已上线后发生的新文章或线索必须保留，不能用旧全库备份覆盖当前库。必要时在独立库恢复备份、核对差异后再受控切换。本轮未执行全库恢复演练，也未在生产环境操作。
